## Shared engine maintenance

`skill.json` declares the runtime engine (webindex), its minimum version and the import floor. The engine bundle in `src/vendor/` is a byte-identical upstream release artifact, pinned by tag, commit and SHA-256 (`src/vendor/webindex.meta.json`); ultrawatch owns its CLI, the citation check and the skill. Prefer upstream engine primitives for generic work — video, retrieval, ranking, claim parsing — and keep only the domain policy here.

Run `pnpm verify:engine` (no engine export re-declared, usage floor held, the pin matches its tag and is not older than the source needs) and `pnpm verify:bundle` (the skill installs whole) to audit the pin and its adoption. To update by hand, run `pnpm exec webindex skill repin`, `pnpm install --no-frozen-lockfile`, then `pnpm engine:prepare`. Review the artifact differences, commit the candidate locally and run `pnpm engine:gate` before pushing. Do not lower the floor or rewrite expectations just to pass: a lower floor is a deliberate change, made in the same commit as the code that stopped using the engine.

The daily workflow (`.github/workflows/engine-repin.yml`) and the development CLI are pinned by immutable commits. The CLI follows stable releases automatically; a maintainer updates the workflow reference separately, since GitHub’s automatic token cannot modify workflow definitions. It validates even when no pin changes, never rebases a tested candidate, and waits for CI and publication; a candidate the gate refuses opens an `engine-repin` issue, closed by the next green run. `pnpm exec webindex skill finish` resumes incomplete publication on the current main commit. The runtime bundle remains self-contained; the maintenance package is development-only.
